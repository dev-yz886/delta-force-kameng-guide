## 一、 多层代理 API 调用链路的雪崩效应

二级、三级卡盟分站通常没有本地库存，仅作为一个前端代理服务器。当访客点击购买时，分站需向总站发起 REST API 请求，总站再向上游供货商调单。任何一个中继节点的带宽受限或 SSL 证书握手超时，都会层层放大请求延迟，最终触发网关 504 Gateway Timeout。

## 二、 识别一手总站与代理分站的特征检测指令

利用网络请求抓包分析商户后端的请求头特征，可准确区分直销与代销平台：

```bash
# 检查响应头中的跨域与反向代理层级
curl -I -s "https://www.991qk.com/api/product/stock"
```

若响应头中出现多个 `X-Forwarded-For` 或 `Via: 1.1 proxy-node`，表明该商户属于多层套壳分销站点；若首选直连总站，响应头通常精炼且单节点直达。

## 三、 提升数据同步稳定性的 API 轮询优化方案

面向商户开发者，推荐在接入三角洲卡盟排行榜的上游货源时，弃用高频短轮询，改用长轮询（Long Polling）或 WebSocket 订阅库存变更事件，将平均拉卡耗时从 1800ms 降低至 120ms 极速水准。
